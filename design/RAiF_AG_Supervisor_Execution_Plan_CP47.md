# RAiF AG Supervisor — план CP-48–CP-56

Дата: 2026-10-10. Ветка: AG_pather.
Цель: Windows-first менеджер аккаунтов Antigravity Standalone: наблюдение, квоты, выбор доступного профиля, управляемое переключение и восстановление задач. Не путать запись в хранилище с работающей авторизованной сессией.

## Базовая точка
CP-31: исправление Language Server испытано.
CP-34/35: пользователь подтвердил редактор, работу модели, квоты и повторный запуск.
CP-45: локальный манифест из 9 записей соответствует схеме.
CP-47: локальный отчёт об импорте показывает SUCCESS, 9 записей в реестре. Доступность самих аккаунтов и переключение не проверены.

## Порядок выполнения

| Этап | Цель | Критерий готовности |
|---|---|---|
| CP-48 | Проверка локального хранилища | 9 зарегистрированных профилей, 9 защищённых записей, нет незавершённой операции. Только агрегированные данные |
| CP-49 | Контрольная проверка одного профиля | Подтверждённый ответ об авторизации или обезличенный код ошибки; корректная обработка тайм-аута и отказа |
| CP-50 | Сбор квот | Для доступных профилей отдельные проверенные 5-часовые и недельные показатели; неизвестное не считается доступным |
| CP-51 | Исследование активной сессии | Установлено, как Standalone обновляет авторизацию, определены границы кэширования Language Server |
| CP-52 | Управляемое переключение | Проверен переход между двумя аккаунтами и возврат к исходному без потери контроля; допускается перезапуск |
| CP-53 | Проверка переключения без рестарта | Совпадают PID и время создания Language Server; подтверждены новая сессия и продолжение задачи. Иначе честный статус UNSUPPORTED |
| CP-54 | Автоматизация | Реакция на подтверждённый лимит, охлаждение, сохранение курсора и восстановление без дублирования действий |
| CP-55 | Интеграция RAiF | Контракты с Control Tower, CKS, RulesHub и локальными инструментами Windows |
| CP-56 | Выпуск | Проверены обновления, сбои, восстановление, установка, тесты и журнал поддержки |

## Жёсткие условия
1. Не повторять импорт и исправление бинарника без установленной причины.
2. Не менять активную авторизацию приложения до отдельного подтверждённого теста CP-52.
3. Безопасность и переносимость: не размещать личные данные, секреты или пользовательские выгрузки в публичном репозитории, CI или диагностических архивах.
4. Для живых запросов и проверки доступа требуется отдельное согласование и соблюдение условий сервиса.
5. Пока смена активной сессии без рестарта не доказана, допускается только сценарий checkpoint → контролируемый перезапуск → resume.
6. Только Windows + PowerShell 7. Без Linux и macOS.

## Контракт доставки
Каждый локальный этап: один ZIP и один PS1 в D:\ЗАГРУЗКИ; одна команда pwsh.exe; итоговый ZIP непосредственно в C:\GIT\Rassvet_AI_Fabric. Полный обезличенный STEPS.jsonl, STATUS, RECEIPT и отчёт. Код и тесты в AG_pather; для кода Windows CI, для документации без CI. После каждого CP: критерии PASS/FAIL, коммит, текущий курсор.

## Текущий курсор
AG_pather → CP-48 READ_ONLY_VAULT_AUDIT → CP-49 CONTROLLED_ONE_PROFILE_TEST → CP-50 QUOTA_OBSERVER.


## CP-48–51 в одном испытании (обновление 2026-10-10)

Пользователь подтвердил: все девять аккаунтов из того же JSON работают в AG-tools. Это основание **не выполнять** повторное массовое обновление OAuth и квот через Google; такая проверка не доказывает применимость той же сессии к Standalone.

**Один пакет** `RAiF_AG_CP48_51_WinAudit.zip` + `RAiF_AG_CP48_51_Run.ps1`:
- CP-48: сравнить 9 зарегистрированных opaque ID с присутствием 9 соответствующих native Generic Credential targets; проверить pending journal.
- CP-49: зафиксировать `USER_REPORTED_AGTOOLS_ONLY`; не читать реальные refresh-токены, не делать OAuth-вызов.
- CP-50: необязательная попытка получить **кэшированные** показатели через локальный API AG-tools `127.0.0.1:19527`; исходники AG-tools помечают этот HTTP API как резервный, поэтому `INTERFACE_UNAVAILABLE` допустим и не считается сбоем. Ответ обрабатывается в памяти, email/ID не записываются. Нового запроса к Google нет.
- CP-51: наблюдение PID/start-time Language Server, количества процессов и соответствия хеша уже пропатченной версии; проверка `hot_swap_verified` по-прежнему false.
- Один итоговый ZIP прямо в `C:\GIT\Rassvet_AI_Fabric`, `STEPS.jsonl` с каждым шагом и обезличенный отчёт.
- CP-52 — **отдельный** эксперимент: реальная смена аккаунта требует согласованного изменения активной сессии и возможности возвращения к исходному состоянию.

Курсор после формирования пакета: `CP-48_51 PACKAGE_PREPARED → RECEIVE_USER_RESULT_ZIP → ASSESS_SCOPE → CP-52 CONTROLLED_SWITCH_DESIGN`.
