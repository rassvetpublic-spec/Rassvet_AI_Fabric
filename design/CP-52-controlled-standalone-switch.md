# CP-52 — проект контролируемого переключения Antigravity Standalone

Дата: 2026-10-10. Ветка AG_pather.
Состояние: DESIGN_ONLY; NO_NATIVE_CREDENTIAL_CHANGE.

## Основание (CP-48–51)
- 9 записей в RAiF Registry и Windows Credential Manager присутствуют; pending journal отсутствует.
- 9 аккаунтов работают в AG-tools по пользовательскому подтверждению; проверка квот с локального API 19527 в последнем запуске не состоялась (AG-tools был закрыт).
- Language Server работает, патч CP-31 сохранился. Идентичность текущего Standalone-профиля и hot swap не доказаны.

## Цель и раздельные проверки
1. Установить минимальный контур `Account handle → token vault → client session` без выдачи токенов в отчёт.
2. Доказать **безопасную смену и возврат** между исходным и одним тестовым аккаунтом. Смена после контролируемого перезапуска допустима и помечается RESTART_REQUIRED.
3. Только после этого отдельно проверять смену без перезапуска с PID+creation-time marker и независимым подтверждением новой идентичности. Непрерывность текущего потока проверяется отдельно.

## Гейты допуска к потенциально изменяющему тесту
- G1: пользователь запускает проверку на своём Windows через PowerShell 7 и явно подтверждает переключение; без подтверждения — только dry-run.
- G2: изолированный Vault содержит 9/9 записей; выбран ровно один тестовый кандидат; запрещён массовый switch всех девяти аккаунтов.
- G3: нативная структура авторизации Standalone изучена только локально и без вывода значений в logs/ZIP. Нельзя собирать native credential из одного лишь refresh_token по предположению.
- G4: до изменения нативного состояния имеется защищённый механизм восстановления исходной сессии, без создания резервной копии самого бинарника; согласие пользователя на такой механизм отдельно фиксируется.
- G5: проверка OAuth кандидата, если необходима, выполняется только на устройстве пользователя для разрешённого аккаунта, с фиксированным доверенным хостом, без redirect с bearer, без логирования токена и с явным статусом результата.
- G6: при заблокированной авторизации, непонятном формате или запрете поставщика результат BLOCKED/UNSUPPORTED; неизвестные байты бинарника не изменять.
- G7: не прерывать текущую генерацию и не закрывать Antigravity автоматически без отдельной команды подтверждения.

## Контракт результата
- Один ZIP и один PS1 в D:\ЗАГРУЗКИ, команда `pwsh.exe -NoProfile -ExecutionPolicy Bypass`.
- Итоговый `RAiF_AG_CP52_RESULT_*.zip` непосредственно в C:\GIT\Rassvet_AI_Fabric.
- `STEPS.jsonl` обязателен для всех этапов, с кодами ошибок и длительностью; строгий allowlist для архивируемых файлов.
- Логи содержат только агрегаты, статусы, факт смены PID/времени запуска и флаги подтверждения. Не включать refresh/access tokens, email, account handles, cookie, SQLite содержимое, пути с личной информацией.
- Программа должна уметь остановиться до любой записи в native Credential Manager и показать dry-run summary.

## Разделение успеха
- `STORAGE_READY` — 9/9 локальных записей.
- `CANDIDATE_AUTH_OK` — выбранный профиль независимо авторизован локально; в CP-48–51 не проверялось.
- `RESTART_SWITCH_OK` — после согласованного рестарта и смены подтверждена новая сессия и возврат; не равно hot swap.
- `HOT_SWAP_OK` — тот же экземпляр LS и подтверждённая новая активная сессия; требует независимого подтверждения.
- `INFLIGHT_RESUME_OK` — сохранённая задача продолжена без дублирования действий; независимо от HOT_SWAP_OK.

## Обнаружение по независимому коду AG-tools (2026-10-10)

- Проверены `lbjlaq/Antigravity-Manager`, файл `src-tauri/src/modules/integration.rs` (публичные исходники, только чтение).
- Для **IDE** в коде описано «hot switch»: записать credentials → завершить **дочерний** `language_server` → дождаться его повторного появления при сохранённом главном окне; возможен откат к полному рестарту.
- Для **classic / native Antigravity Standalone**, по текущему условию `if is_ide && running`, этот путь не исполняется. При работающем классическом приложении логика использует `close_antigravity`, затем `start_antigravity_with_fallback_path`, то есть полный restart.
- Запись в `gemini:antigravity` сама по себе не подтверждает, что уже запущенный language_server перечитал новые значения. Алгоритм AG-tools также требует предварительного обновления токена перед переключением.
- Это объясняет, почему пользователь наблюдал отсутствие горячего переключения Standalone в AG-tools, но не доказывает, что сохранение главного окна технически невозможно.
