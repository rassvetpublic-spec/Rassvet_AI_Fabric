Дата: 2026-10-10. Пользователь подтвердил: резервные копии оригинала не создавать; восстановление при необходимости — переустановка Antigravity.

## Проблема
- На скриншоте Antigravity 2.0 остаётся на экране Welcome / Sign in после сообщения об успешной авторизации в браузере.
- Пользователь сообщает, что ранее такую ситуацию исправлял бинарный патч `language_server.exe`.
- Это наблюдение не доказывает, что текущая причина — именно локальная eligibility-проверка: возможны проблемы с callback, региональным доступом, связью бэкенда с Google и т.д.

## Ограничения патчера
- Только Windows x64, только локальный `language_server.exe` Antigravity 2.0.
- Использует известную сигнатуру `authclient.(*PersonalAuthValidator).Validate / hasValidAuth` из QNIX-Dev/eligibility-antigravity-patcher (MIT). В комплекте ATTRIBUTION.txt.
- До записи проверяет PE, исполняемую секцию, уникальность оригинальной/уже изменённой сигнатуры, отсутствие запущенных Antigravity.exe и language_server.exe. 
- При точном единственном совпадении заменяет только 6 байт, перечитывает бинарник и проверяет новое состояние. Не копирует исходный файл в .bak, tmp или ZIP; отчёт хранит только размер, SHA-256, смещение, безопасный статус.
- Несовместимая сигнатура, архитектура, нет файла или приложение ещё работает → отказ без модификации, результирующий ZIP сохраняется для диагностики.
- Запускатор проверяет SHA-256 скачанного ZIP перед распаковкой; PowerShell ExecutionPolicy Bypass действует только в запускаемом процессе.
- Никаких OAuth tokens, Credential Manager, SQLite, email, файлов учётных записей, сети, автозакрытия процессов и обновления пакета.

## Проверки перед выдачей
- Синтетические PE-тесты: 5/5 success на исходной, уже патченной, неоднозначной, ARM и неподдерживаемой сигнатуре.
- ZIP CRC success, целостность hash vs PS1 verified.
- Безопасное завершение на не-Windows машине с exit code 3, без попытки правки, с отчётом not_applied.
- Runtime Windows результат НЕ подтверждён; нужен результирующий ZIP от пользователя.
- После патча вендорская цифровая подпись бинарника может стать недействительной; при невозможности запуска рекомендована переустановка. Автоматического rollback нет по требованию пользователя.
- Возможны расхождения версий: сигнатура QNIX подтверждена для отдельных сборок, но конкретный текущий `language_server.exe` пользователя пока неизвестен.
- Клиентский патч не создаёт серверные права, не гарантирует доступность сервиса в регионе и может противоречить условиям Google.
