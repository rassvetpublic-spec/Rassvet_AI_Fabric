# Скилл безопасного удаления чата (/del)

Этот скилл запускается по команде `/del` в **любом репозитории флота или изолированном проекте**. Он гарантирует, что ни одна строчка ценного кода, гипотеза, архитектурная идея или предложенная задача не пропадет при удалении окна чата.

---

## 🛠️ Алгоритм работы (Строгий канонический порядок)

### Шаг 1. Первичный аудит и обновление каталогов
1. **Обновить каталоги скриптов (если применимо)**:
   - Если в текущем проекте есть `scripts/generate_catalog.py`, запустить `python scripts/generate_catalog.py`.
   - Если есть тесты или самодиагностика (`scripts/integrity_guard.py`, `scripts/pre_push_gate.py`, `tools/tower_self_audit.py`, `tools/verify_fleet_mcp_clients.py`), проверить чистоту контура.
2. Внимательно проанализировать всю историю текущего чата (transcript) снизу вверх.
3. Найти все фрагменты кода, "супер-идеи", решения и задачи, которые еще не были сохранены на диск, не отправлены в Issue или не опечатаны.

### Шаг 2. Автоматическое сохранение невыполненных предложений (No Dropped Proposals)
1. Выделить все не вошедшие в текущую сессию рекомендации горизонта `[Класс A/B/C - X/Y/Z]`.
2. Если доступен инструмент `tools/proposals_preserver.py` (в `CONTROL_TOWER`), вызвать его для автоматической регистрации GitHub Issues в целевых репозиториях и записи в `telemetry/unaccepted_proposals.json`.
3. Если инструмент недоступен — зарегистрировать открытые предложения через `gh issue create` в репозитории текущего проекта или зафиксировать их прямо в отчёте удаления.
4. При наличии других неструктурированных идей задать уточнение через `ask_question`.

### Шаг 3. Вторичная верификация и статус Git
1. Проверить `git status` текущего проекта. Все готовые изменения должны быть закоммичены либо явно учтены.
2. Проверить статус сопряжённых репозиториев, если в чате велась сквозная работа.
3. Рассчитать метрику потерь (Loss Threshold): процент ценной информации, которая исчезнет при удалении чата (целевой показатель: 0.0%).

### Шаг 4. Генерация комплексного отчёта всей сессии (Session Work Ledger)
1. Собрать единый всеобъемлющий отчёт о всей проделанной работе в текущем чате с фиксацией:
   - Всех решённых архитектурных задач и созданных модулей/паспортов.
   - Полной хроники коммитов Git (с SHA-хэшами) под мандатом MTD.
   - Сводного реестра созданных/изменённых файлов и тестовых сьютов.
2. Сохранить отчёт на диск по динамическому пути сохранения:
   - `<REPO_ROOT>/docs/reports/SESSION_FULL_WORK_REPORT_<YYYYMMDD>_MTD.md` (или `<REPO_ROOT>/docs/history/delete_audit_<session_id>.md`).
3. Зарегистрировать официальный пользовательский UI-артефакт платформы Antigravity (`write_to_file` с `ArtifactMetadata`) в `<appDataDir>\brain\<conversation-id>`.

### Шаг 5. Обязательный сброс в Input Box (Visible Chat Mirroring)
Финальный дайджест и полный текст отчёта **ОБЯЗАТЕЛЬНО полностью выводятся в чат** (видимый ответ агента в input box), чтобы пользователь видел исчерпывающую картину без необходимости открывать внешние файлы.

### Шаг 6. Анализ векторов развития и заморозки (Active Tracks vs Frozen vs Obsolete)
В отчёте и чате обязателен аналитический блок метрик направлений:
1. 🚀 **Развивается (Active Evolution):** модули, архитектурные слои и сервисы, получившие апгрейд, расширение тестов, sidecar-паспорта и индексацию в графе знаний.
2. ❄️ **Заморожено / На паузе (Frozen / On-Hold):** направления, ожидающие внешних событий (например, PR #324 до получения конверта Controller, бранчи в архиве, очереди слияния).
3. 🛑 **Брошено / Устарело (Obsolete / Graveyard):** депрекейтнутые концепты, дубликаты правил, исключённые неэффективные подходы или временные заглушки.

### Шаг 7. Трассировка судьбы отправленного (Dispatch & Provenance Tracker)
Обязательная сквозная проверка и доказательство физической сохранности данных:
1. **Башня 1 (Локальный SSD):** абсолютные пути к сохранённым файлам отчётов и модулей в локальных репозиториях (`KAT9I_OS`, `CONTROL_TOWER`, `BPR40`).
2. **Башня 2 (GitHub Remote):** подтверждение отправки в remote origin, номера коммитов и прямые ссылки на GitHub Blob/Commits.
3. **Башня 3 (Google Drive Mirror):** подтверждение зеркалирования в облачный диск флота (`C:\Gdrive_RassvetPublic\...`).
4. **UI-артефакт Antigravity:** путь к файлу в директории сессии `<appDataDir>\brain\<conversation-id>`.
5. **Криптографический консенсус SHA-256:** расчёт контрольной суммы SHA-256 файла отчёта и подтверждение бит-в-бит идентичности на всех эшелонах (Zero Drift).

## 📊 Структура финального отчёта

1. **Дайджест сохранения**: Таблица с абсолютными путями к изменённым файлам и ссылками на коммиты/PR/Issues.
2. **Метрический срез векторов (Развивается / Заморожено / Брошено)**.
3. **Трассировка судьбы отправленного (Dispatch & Provenance Table с хэшами SHA-256)**.
4. **Список потерь**: Перечисление удаляемых данных (только эфемерные логи UI и отладочный вывод).
5. **Визуализация сохранности**:
   `Сохранность контекста: [████████████████████] 100% (Потери: 0.0%)`
6. **Финальная плашка безопасного выхода**:
   > [!TIP]
   > **Удаляй этот чат — безопасно сохранено в:**
   > - <перечисление локальных файлов, коммитов, артефактов и ссылок на Issues>
