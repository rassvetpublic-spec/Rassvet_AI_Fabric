# Офлайн-контракт Codex App Server

**Этап:** `RAI-FABRIC/09.0`. **Статус:** локально протестированный протокол; работа с подпиской и внешним процессом ещё не подтверждена. **Язык:** русский.

## Назначение

Модуль `src/rai_fabric/codex_protocol.py` задаёт обязательную последовательность обмена с официальным Codex App Server без запуска процесса, OAuth, сети, моделей или чтения учётных данных. Это оригинальный контракт Fabric, не копия стороннего runtime.

Последовательность запросов:

1. `initialize` с постоянным `clientInfo.name=rassvet_ai_fabric` и русским именем клиента.
2. Только после успешного ответа — уведомление `initialized`.
3. `thread/start` с явно выбранной моделью и отдельным каталогом. Контракт по умолчанию требует `sandbox=readOnly` и `approvalPolicy=unlessTrusted`.
4. Только после подтверждённого `thread.id` — `turn/start` с текстовым элементом `input`.
5. Запись `turn.id`, сбор ограниченного потока `item/agentMessage/delta`, проверка принадлежности событий правильным `threadId`/`turnId`.
6. **Только** `turn/completed` и `turn.status=completed` дают транспортный `PASS`. При этом курсор — `REVIEW_EVIDENCE`, а не приёмка результата в BPR40.

## Строгие блокировки

| Ситуация | Реакция |
|---|---|
| Неожиданный ответ или нарушенный порядок RPC | `BLOCKED`, требуется сверка |
| Неизвестные `threadId` или `turnId` | `BLOCKED`, исключаем смешивание сессий |
| Сервер запросил подтверждение или выполнение команды | `BLOCKED` и `MANUAL_SERVER_REQUEST`; автоматического одобрения нет |
| Отсутствует `turn.id`, `thread.id` | `BLOCKED` |
| Получен `turn.status=failed/interrupted` | `BLOCKED`, курсор `VERIFY_EXTERNAL_SIDE_EFFECTS` |
| Получен `item/completed` без `turn/completed` | Считаем промежуточным уведомлением, итог не подтверждён |
| Превышен лимит пакета/вывода | `BLOCKED` |

Транспорт и проверка OAuth будут самостоятельными модулями. Секреты нельзя помещать в stdout, task evidence, аргументы shell, Git и отчёты.

## Границы достигнутого

- Сейчас есть только **проверяемая офлайн-модель обмена**, не работающий подключённый Codex worker.
- Нет действующего процесса `codex app-server`, авторизации, API-запросов, подписной квоты, обновления токенов и управления реальными разрешениями.
- `model/list` может вернуть локальный каталог и не доказывает право на inference; успех проверяется **реальным завершённым turn** только после явного разрешения оператора.
- Разрешения на запись и работу с Git будут определены отдельно, без автоматического повышения прав.
- HTTP/curl/DOM доступ к потребительской странице ChatGPT не используется.

## Дальнейшие проверки

1. Полный обмен через stdio с подставным (mock) дочерним процессом, без модели.
2. Тайм-ауты, отмена, завершение дерева процессов Windows, устойчивость к неполному выводу.
3. Настройка OAuth с PKCE, проверкой подписи ID токена, scopes и защищённым хранилищем; только на подходящем тарифе.
4. Один явно подтверждённый подписной inference; токены/секреты не попадают в журнал, платный fallback запрещён.
5. Сохранение `threadId` в собственной БД с checkpoint; затем `thread/resume` после смены токена.

Официальные спецификации: [App Server](https://learn.chatgpt.com/docs/app-server), [Sign in with ChatGPT / Codex App Server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server), [ограничения режима](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

## Испытания реального stdio с подставным процессом (этап 09.1)

Добавлены два оригинальных модуля `codex_mock_server.py` и `codex_mock_transport.py`: клиент запускает **только** известный локальный имитатор через системный Python в изолированном режиме (`-I`), без оболочки и без передачи окружения авторизации. Настоящий `codex` и AI-провайдеры **не запускаются**.

Сценарии проверки: нормальное завершение, ошибка `turn`, неожиданный запрос разрешения, тайм-аут, потеря stdout/EOF, отсутствие секрета в окружении и проверка недопустимых параметров. Транспорт закрывает дочерний процесс, ограничивает время и число сообщений. Контракт не подтверждает остановку *дерева* дочерних процессов на Windows (для настоящих workers нужны Job Objects).

Статус на момент подготовки: **76/76 локальных тестов PASS**, Windows CI новой ревизии ещё не выполнен. Это не подтверждение OAuth, подписки, лимитов либо права управлять реальным Codex по сети.
