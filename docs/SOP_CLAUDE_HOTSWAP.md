# SOP: Регламент горячего переключения на модели Claude (CP-55)

**Версия:** 1.0.0  
**Стандарт:** BPR5 NextGen (v5.1.0-alpha / R3.3) / CP-55  
**Статус:** ACTIVE / PRODUCTION_READY  
**Приоритет безопасности:** `PRIVACY > SECURITY > DATA_INTEGRITY > KNOWLEDGE > AUTO-SYNC`

---

## 1. Назначение и контекст

Данный регламент (Standard Operating Procedure) определяет порядок действий оператора и автоматических диспетчеров RAiF при необходимости переключения с моделей Google Gemini на модели Claude (Anthropic).

### Ключевые цели
1. **Преодоление лимитов квот (Rate Limiting):** Мгновенная реакция на HTTP 429 (Too Many Requests) или 503 (Service Unavailable) без остановки задач флота.
2. **Оптимизация расходов и квот:** Вынос рутинных синтетических задач на быстрые экономичные модели (Claude 3.5 Haiku).
3. **Единый биллинг и безопасность:** Использование того же Google-аккаунта (Vertex AI Partner Models / Antigravity Model Selection) без хранения открытых ключей API сторонних сервисов.

## 3. Режимы переключения

### 3.1. Ручной режим (Antigravity IDE Model Selection)
*Применяется оператором непосредственно в активной сессии диалога.*

1. **Обнаружение события:**
   - Появление сообщения об исчерпании квоты (429) или деградации ответа.
   - Необходимость альтернативной экспертизы сложного архитектурного блока.
2. **Шаги оператора:**
   - В правом верхнем углу интерфейса чата Antigravity открыть выпадающий список **Model Selection**.
   - Выбрать соответствующую модель (например, `Claude 3.5 Sonnet` или `Claude 3.7 Sonnet (Thinking)`).
   - Убедиться, что системный контекст BPR5 сохраняется в заголовке ответа.
3. **Инвариант возврата:**
   - После завершения пикового периода или сброса окна квоты оператор возвращает основную модель через тот же переключатель.

### 3.2. Автоматический программный режим (RAiF Failover Router)
*Применяется для автономных воркеров и очередей задач через `FailoverRouter` и `ClaudeVertexTransport`.*

1. **Триггеры автоматического перехода:**
   - Ошибка сетевого транспорта с кодом `RATE_LIMITED` или HTTP статус `429`.
   - Недоступность основного API `SERVICE_UNAVAILABLE` (HTTP `503`).
   - Исчерпание порога повторных попыток (`retry_budget = 2`).
2. **Автоматическая цепочка переключения:**
   ```
   [Primary: Gemini Transport] --(429/503)--> [Fallback 1: Claude Haiku] --(Error)--> [Fallback 2: Claude Sonnet]
   ```
3. **Восстановление (Return to Primary):**
   - Фоновый probe-опрос первичного канала с тайм-аутом 3 секунды.
   - При успешном probe primary-канала роутер автоматически возвращает исполнение на основную модель (`RETURN_TO_PRIMARY_ON_RECOVERY`).
4. **Метрики Zero SSD Wear:**
   - Все события переключения передаются в оперативной памяти через `FleetMetricsBridge` (`model_switches_total`, `fallback_active`, `fallback_duration_seconds`).

## 4. Инварианты безопасности флота

1. **Инвариант SECRETS_GATE:** Запрещается сохранение незашифрованных токенов `ANTHROPIC_API_KEY` в репозитории или переменных окружения без DPAPI. Предпочтительный транспорт — Google Cloud ADC.
2. **Инвариант FAIL_CLOSED:** При одновременной недоступности обоих поставщиков задача переводится в статус `BLOCKED_WAITING_QUOTA` без повторных зацикливаний и потери очереди.
3. **Инвариант Изоляции Контекста:** Каждый failover-сегмент валидирует цифровую подпись конверта (`TransportMessageEnvelope.verify_signature()`).
