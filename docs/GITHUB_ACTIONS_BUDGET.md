# Политика экономии GitHub Actions — Rassvet AI Fabric

**Статус:** обязательное правило с 10 октября 2026 года. **Официальный язык:** русский.

## Цель и границы

Проект предназначен для Windows. GitHub Actions не используют Linux, macOS, произвольные larger runners и не заменяют тестирование на личном компьютере. Выбор Windows — архитектурное требование пользователя, даже когда другой runner мог бы быть дешевле.

## Основная ветка main

- Автоматическая проверка запускается только при изменениях `src/**`, `tests/**`, `scripts/**`, `pyproject.toml` или `.github/workflows/windows-readonly.yml`.
- Изменения исключительно README, docs, checkpoints или манифеста SHA256 не создают новый CI-run.
- Каждый обычный push или PR запускает **одно** Windows-задание с Python 3.11, а не матрицу.
- При явном ручном `workflow_dispatch` можно выбрать Python 3.11 или 3.13. Повторять обе версии на каждый коммит не нужно.
- Есть `timeout-minutes: 12`, минимальные разрешения и `cancel-in-progress: true`.

## Ветка AG_pather

- Текущий workflow `AG_pather` запускает один Windows job только при изменениях `src/**`, `tests/**`, `pyproject.toml`, разрешённого тестового скрипта или самого workflow. Push, затрагивающий только документы и чекпойнты, не запускает CI.
- Явные контрольные ветки/теги `ag-ci-win-*` допускаются; конфигурация не содержит Linux job.
- Одно Windows-задание, Python 3.12, ограничение 7 минут. При переходе репозитория в private задача пропускается. Перед изменением ветки нужно заново считывать её актуальный HEAD и workflow: параллельная работа может обновлять настройки.
- Старые контрольные ветки с историческими Linux-workflow сохранены для provenance; не выполнять по ним новые push без отдельной миграции или закрытия по gate.

## Контроль объёма и предупреждения

- Ежечасно без запуска тестов анализировать число запусков и jobs за 1/24 часа, ОС, статусы и длительность, отдельно ветку `AG_pather`.
- Предупреждать при более 5 запусках в час или более 10 в день, любом новом Linux/macOS job, новой схеме автозапуска, больших платных runners, переходе в private, длительных ошибках либо подтверждённом расходе более 70% лимита.
- Не выводить несуществующие показатели расхода: доступ к точным Billing/Usage API может отсутствовать у подключённого GitHub-интерфейса.
- Не использовать GitHub Actions как watchdog непрерывной работы: наблюдение — чтение метаданных, разработка — локальная.

## Текущий статус и биллинг

По состоянию на 10 октября 2026 года репозиторий публичный. Стандартные GitHub-hosted runners для публичных репозиториев бесплатны по действующим правилам GitHub; это не означает отсутствие эксплуатационных ограничений, цен на larger runners или затрат на хранение. Смена на private требует пересмотра бюджета.

На момент первого аудита было зарегистрировано 32 запуска за примерно 35 минут: 20 запусков `AG Supervisor Tests` на `AG_pather`, 2 на контрольных ветках и 10 запусков основного Windows CI. Это исторический снимок, а не текущее значение.

## Проверка и контроль

Для локальной разработки основной тест: `./scripts/run-tests.ps1`. При изменении самого workflow достаточно одного управляемого Windows-прогона. После подтверждённого CI фиксируются ссылка на точный run ID и курсор. Не изменять внешние BPR40/CONTROL TOWER без отдельного разрешения.
