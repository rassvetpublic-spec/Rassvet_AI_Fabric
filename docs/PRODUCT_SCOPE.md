# Целевая архитектура Rassvet AI Fabric

**Версия документа:** 1.0. **Дата:** 10 октября 2026 года. **Статус:** проектное решение, не подтверждённое интеграционными испытаниями. **Язык:** русский.

## 1. Назначение и границы

Rassvet AI Fabric — личная Windows-first платформа **разработки приложений и подсистем**, а не очередной AI-чат, модель и не новый источник истины. Она обеспечивает диспетчеризацию разработки, локальные инструменты, проверяемые результаты, экономию облачных вызовов и продолжение работ после сбоя.

Целевой проект состоит из `KAT9I_OS`, `CKS`, `RULESHUB`, `ANTIGRAVITYDATA`, `CONTROL TOWER`. Они сохраняют независимые репозитории, контракты, права на изменения и происхождение данных. Fabric не объединяет их содержимое физически и не выполняет автоматическую «промоцию» решений в канон.

| Домен | Владелец | Граница ответственности Fabric |
|---|---|---|
| Продукт и выполнение | `KAT9I_OS` | Вызывает инструменты в разрешённом workspace, возвращает diff и evidence; не переписывает продуктовый control plane |
| Проверенное знание | `CKS` | Читает действующие правила выдачи знаний; передаёт кандидаты на валидацию, не пишет напрямую в Canon |
| Политики и навыки | `RULESHUB` | Разрешает правила и ссылается на версии; не создаёт параллельный реестр политик |
| Операционные следы | `ANTIGRAVITYDATA` | Забирает только разрешённые артефакты, сохраняет provenance; не выдаёт сырые записи за проверенное знание |
| Управление и авторизация | `CONTROL TOWER` | Выполняет readback authority/Router/BPR40; публикация checkpoint только после отдельного gate |

Для CONTROL TOWER учитывается актуальный authority readback, а не сведения, случайно найденные поиском. Не следует переносить сюда внутренние контрольные документы или их идентификаторы без отдельной проверки права публикации.

## 2. Разделение рабочих каналов

| Канал | Интерфейс | Автоматизация | Учёт расхода |
|---|---|---|---|
| ChatGPT Web | Человек → веб-чат; разрешённый MCP при наличии доступа | Интерактивный; **не** автоматический DOM/curl-proxy | Лимиты веб-интерфейса согласно плану |
| ChatGPT plan | Sign in with ChatGPT → Codex App Server → Responses | Да, если разрешён OAuth, клиент и модель | Общая применимая квота ChatGPT/Codex, не безлимит |
| Antigravity | Самостоятельный IDE/CLI с общими Git-артефактами | Внутренне одобренное проектирование Supervisor, наблюдения и управления пулом | Лимиты и условия провайдера; runtime-автоматизация только после отдельного gate |
| Gemini программно | Официально разрешённый Gemini/Vertex API | Только отдельное явное включение | Может потребовать отдельной оплаты |
| Локальное выполнение | PowerShell, Git, тесты, SQLite, RTX 5070 Ti | Да, локальные sandbox/политики | Нет облачной платы за inference; есть энергозатраты |

**Ключевое различие:** подписное вычисление ChatGPT через OAuth не тождественно автоматическому запросу к странице `chatgpt.com`. Правила OpenAI запрещают программно извлекать ответы из потребительского веб-интерфейса и обходить лимиты. Условия SIWC требуют: только подключённое приложение, пользовательское управление и согласие на фоновую работу; нельзя предоставлять универсальный API-прокси для посторонних инструментов.

По директиве владельца `MTD 011011` целевое проектное направление Antigravity — собственный супервизор (`raif_ag_supervisor`) и исследование управления пулом аккаунтов, Child Respawn и loopback proxy. Внутреннее решение предусматривает **автоматическую ротацию аккаунтов** как исследуемую целевую возможность, а не как действующий и допущенный runtime. Механизмы переключения при квотных ошибках рассматриваются как **цель и гипотеза**, а не доказанная функция: 429 и 403 необходимо классифицировать по коду и причине; бесшовный in-flight replay, задержки и сохранность сессии пока не подтверждены живыми испытаниями. Проверка допустимости OAuth/типа аккаунта/программного интерфейса и независимый gate требуются **до** подключения к реальному провайдеру. Внутреннее решение владельца не изменяет правила поставщика.

## 3. Логическая архитектура

```text
                      ПОЛЬЗОВАТЕЛЬ
                          |
          +---------------+---------------+
          |                               |
    ChatGPT Web (UI)            Консоль/HUD Fabric
    ручной контроль             локальные задачи
          |                               |
     разрешённый MCP                 RAI Coordinator
          |                               |
          +-----------+-------------------+
                      |
                TASK / CURSOR
                      |
       +--------------+-------------------+
       |              |                   |
   Codex App       Local Tools       Экспорт артефактов
   Server +        Git / PS1 /       в независимые IDE
   SIWC OAuth      GPU / Test               |
       |              |                  Antigravity
       +--------------+-------------------+
                      |
                 EVIDENCE / DIFF
                      |
               BPR40 Readback/Gate
                      |
             CONTROL TOWER (authority)
```

У Fabric собственные *операционные* SQLite-задачи, но он не становится нормативным SSOT. Даже `COMPLETE` в локальной очереди — не подтверждение приёмки CONTROL TOWER или CKS.

## 4. Независимые модули Fabric

1. **Workspace Registry:** разрешённые проекты, ссылки на source-of-truth, ограничения файловых мутаций, commit pinning.
2. **Task Graph:** зависимости, арендные блокировки, heartbeat, отмена, идемпотентность, ограниченная параллельность.
3. **Execution Adapter:** штатные способы запуска собственного Codex App Server, локальных инструментов и разрешённых провайдеров; без захвата cookie.
4. **Model Budget Router:** тип задачи, стоимость облачного обращения, размер контекста и остаток квоты; fail-closed при неизвестном биллинге.
5. **Skills & Verification Pipeline:** спецификация → план → тесты → реализация → независимое ревью → QA, с возможностью использовать Git worktrees.
6. **MCP Gateway:** узкие интерфейсы и политики доступа, не универсальная удалённая оболочка.
7. **Checkpoint & Evidence Bridge:** атомарные события, привязка к Git SHA, проверка результата, курсор, отдельный gate BPR40.
8. **Observability:** рабочий курсор, task graph, процессы, сбои, попытки, использование квот, GPU, доказательства тестов.

Паттерны команд агентов, наблюдаемости, планирования, TDD, ревью, изолированных рабочих каталогов и верификации можно реализовать независимо от реализации какого-либо стороннего фреймворка. Обзор исследованных доноров вынесен из README в отдельную [техническую записку](ENGINEERING_REFERENCES.md).

## 5. Инварианты безопасного выполнения

- Каждая задача привязана к одному проекту, authority readback, точному git ref/commit и разрешённому набору файлов.
- Непроверенное содержимое репозитория, логов и чатов не может переопределять политики или запускать произвольные команды.
- Чекпойнт — результат проверяемого этапа; в нём есть следующий cursor и evidence, а не только текст «готово».
- После обрыва или потери lease задача остаётся `BLOCKED` до проверки внешних побочных эффектов.
- Подписная авторизация хранится отдельно и защищённо; секреты не пишутся в Git, CKS, журналы и ответы MCP.
- Любые платные облачные вызовы выключены, пока пользователь не разрешит их явно. Ротация аккаунтов и проксирование — одобренные владельцем архитектурные цели; эксплуатация только после отдельного gate по допустимости провайдера и живым испытаниям.
- Прямой путь `raw runtime → CKS Canon`, неавторизованные изменения RULESHUB/CONTROL TOWER и автоматический массовый merge запрещены.

## 6. Ближайший доказуемый сценарий

В изолированном рабочем каталоге RAI Fabric читает статус тестового проекта, составляет минимальный контекст, создаёт задачу, вызывает *разрешённый* программный канал Codex App Server с подписным OAuth, получает структурированный результат, выполняет локальные тесты и записывает курсор. Отдельно проверяются возможности интерактивной работы ChatGPT Web с MCP и ручной обмен файлами с Antigravity. Внешние каналы не объявляются готовыми до живых испытаний.
