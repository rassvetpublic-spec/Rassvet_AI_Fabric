# Реальный Codex App Server — безопасный поток без inference (09.9)

**Дата:** 10 октября 2026. **Статус:** исходники и синтетические тесты готовы, проверка на пользовательском Windows ещё не завершена.

## Зачем этот этап

Этап 09.8 доказал реальный `initialize` установленного Codex App Server на Windows. Этап 09.9 переводит транспорт в собственный модуль Fabric `src/rai_fabric/codex_real_transport.py` и добавляет следующий системный шаг: `thread/start` без отправки пользовательского prompt.

## Обмен

1. Только заранее проверенный `codex.exe` (путь и SHA-256), `app-server --listen stdio://`, в отдельном `CODEX_HOME`.
2. `initialize`, ожидание результата с `id=1`, затем `initialized`.
3. В режиме `thread` — `thread/start` с `model=null`, `cwd` изолированного тестового workspace, `approvalPolicy=never`, `sandbox=readOnly`, `ephemeral=true`; ожидание результата с `id=2`.
4. **`turn/start` отсутствует в исходном коде транспорта.** Приходящий запрос разрешения или чужой `id` блокирует обработку.
5. Завершение собственного дочернего процесса, контроль timeout/EOF и очистка собственного дерева Windows при необходимости. Статус `CLEANUP_NOT_VERIFIED` не может дать PASS.
6. Результат содержит только статусы, названия отправленных методов, длительность и сокращённый SHA-256 идентификатора потока. Сырой stdout/stderr, пути и токены не возвращаются.

`thread/start` может инициировать внутреннюю загрузку метаданных модели самим Codex: отсутствие `turn/start` означает отсутствие **запрошенного Fabric inference**, а не криптографическое доказательство отсутствия любого сетевого соединения дочернего процесса. `model/list` (если будет добавлен) не подтверждает доступ по подписке. Право на модель подтверждается лишь отдельным явно разрешённым полноценным запросом.

## Приёмка и ограничения

- Локальный синтетический набор: 191 тест обнаружен, 184 PASS, 7 Windows-зависимых пропущены; без ошибок. Успех на Linux-среде сборки не считается Windows-подтверждением. Новые Linux jobs не создаются.
- Публикация кода вызывает не более одного предусмотренного Windows CI на main; финальный чекпойнт после CI должен быть отдельным документационным коммитом без повторного запуска Actions.
- Обязателен живой результат на пользовательском Windows с реальным `thread_created=true`, `method_names_sent` строго `initialize, initialized, thread/start`, и подтверждённой очисткой дочернего процесса.
- Ни авторизация OAuth, ни реальный turn, ни `codex-app` как исполнитель SQLite пока не включены. Доступ к пяти проектам остаётся за authority gate, в том числе BPR40 и CONTROL TOWER.
