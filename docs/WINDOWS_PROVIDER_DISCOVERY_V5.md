# Windows: обнаружение провайдеров по процессам — v5

**Официальный язык — русский.** Статус: READY_NOT_RUN; при проверке Windows потребуется пользовательский запуск.

Комплект: `RAiF-Windows-Discovery-09_7D.zip` и `Start-RAiF-Discovery-v5.ps1`.
Оба файла помещаются в `D:\ЗАГРУЗКИ`. Используется PowerShell 7 (pwsh.exe).

Запуск: `pwsh.exe -NoProfile -ExecutionPolicy Bypass -File "D:\ЗАГРУЗКИ\Start-RAiF-Discovery-v5.ps1"`

Выход: один `C:\GIT\Rassvet_AI_Fabric\RAiF-Windows-RESULT-DISCOVERY-*.zip`.

## Границы

1. Проверка подписанных в ZIP файлов по SHA-256; запуск сканера только после успешной проверки.
2. `Win32_Process.CommandLine` используется в памяти для обнаружения Codex и Antigravity. Полные аргументы процессов не сохраняются; экспортируются только PID, имя, путь исполняемого файла и безопасный маркер запуска.
3. Git проверяется после сканирования. Если его нет — `winget install --id Git.Git --exact --source winget --scope user --silent --disable-interactivity` с принятием соглашений. Установка меняет систему по запросу пользователя. В некоторых версиях пакета Git.Git может запрашиваться UAC даже при `--scope user`: не подтверждать повышение прав, если оно нежелательно.
4. Журнал транскрипта, `STAGES.jsonl`, сообщения сканера, stdout/stderr winget и контрольный чекпойнт помещаются внутрь результирующего ZIP.
5. Никакой OAuth, запуск моделей, чтение файлов авторизации, изменение BPR40 или CONTROL TOWER не выполняются.
6. Ошибка предыдущей v4: `.Count` на не-массиве. В v5 коллекции явно приводятся к массивам, ошибочный результат v4 остаётся историческим evidence.

## Приёмка

Сначала получить ZIP пользователя. Проверить `CHECKPOINT.json` и этапы, затем `PROVIDERS.json`. Нельзя объявлять PASS по исходному ZIP или только по статическому анализу PS1.
GitHub Actions не запускать для файлов `delivery/windows`, `docs`, `checkpoints`.
