# Rassvet AI Fabric — Windows-проверка Codex App Server 09.8

**Дата:** 10 октября 2026 года. **Статус:** `READY_NOT_RUN` — пакет проверен статически, на компьютере владельца ещё не исполнен. **Среда:** Windows + PowerShell 7; Linux/WSL не требуются.

## Цель и узкая граница

Проверить работу настоящего `codex.exe app-server --listen stdio://`, не запускать рассуждения или работу с репозиторием. Допустимая последовательность JSONL по официальному протоколу OpenAI:

1. Отправить `initialize` с `clientInfo` (`rassvet_ai_fabric`).
2. Получить ответ с тем же `id` и полем `result`.
3. Отправить уведомление `initialized` без `id`.
4. Закрыть **только созданный диагностикой** дочерний процесс.

Запросов `thread/start`, `turn/start`, `account/read`, OAuth, чтения существующих сессий, модели или платного API нет. Успешный handshake **не подтверждает право использования квоты подписки**. App Server может выполнять собственные начальные операции; отсутствие любого исходящего соединения всей программы отдельно не аттестовано.

## Передача на Windows

Скачать два файла в `D:\ЗАГРУЗКИ`:

- `RAiF-Codex-Handshake-09_8.zip`
- `Start-RAiF-Codex-09_8.ps1`

Одна команда:

```powershell
pwsh.exe -NoProfile -ExecutionPolicy Bypass -File "D:\ЗАГРУЗКИ\Start-RAiF-Codex-09_8.ps1"
```

Запускатор проверяет закреплённый SHA-256 ZIP, разрешённые имена внутри архива и SHA-256 отдельного PS1. Он создаёт только временные каталоги внутри `C:\GIT\Rassvet_AI_Fabric\.rai-fabric\windows-validation\runs` и один ZIP результатов **непосредственно в корне проекта**:

`C:\GIT\Rassvet_AI_Fabric\RAiF-Windows-RESULT-CODEX-*.zip`

ZIP содержит `CHECKPOINT.json`, `STEPS.jsonl`, `PROBE.json`, `PROBE_STAGES.jsonl` (последние два — при достижении соответствующего этапа). Полные аргументы процессов, stdout/stderr, токены, user profile paths и секреты **не упаковываются**. Код ошибок сериализуется только как безопасный тип/категория.

## Принципы безопасности

- Поиск `codex.exe` ограничен каталогом `%LOCALAPPDATA%\OpenAI\Codex\bin` и путями уже запущенных `codex.exe` внутри него. Путь из чужого каталога не исполняется. Существующие процессы не останавливаются.
- Для нового дочернего процесса используется **отдельный пустой `CODEX_HOME`**. Передаваемая среда формируется из разрешённого списка системных переменных, без API-ключей и токенов.
- Рабочий каталог нового процесса — изолированная тестовая папка, не исходники KAT9I_OS/CKS/RULESHUB/ANTIGRAVITYDATA/CONTROL TOWER.
- Тайм-аут ответа `initialize` — 18 секунд. При завершении останавливается только созданный дочерний процесс и его дочернее дерево, если штатное закрытие не сработало.
- Никаких установок приложений, изменений существующих профилей/авторизации, обновлений GitHub или GitHub Actions.
- На отказе создаётся диагностический ZIP с `BLOCKED`; отсутствие ответа нельзя считать успешно подтверждённой подпиской.

## Границы приёмки

`PASS_WITH_SCOPE` — процесс реального Codex App Server ответил на `initialize` и принял отправленное уведомление `initialized` на стороне клиента. **Приём уведомления сервером отдельно не подтверждается** без дополнительной команды, которая здесь не выполняется. `BLOCKED` — исполнитель не найден, старт не удался, ответ отсутствует либо некорректен. `PARTIAL` — проблемы штатного завершения при ранее полученном ответе.
