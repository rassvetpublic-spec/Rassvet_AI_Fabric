# OAuth: обмен кода и обновление токенов — этап 09.6

**Статус:** автономный офлайн-контракт; **не** действующий сетевой клиент. **Официальный язык:** русский.

## Назначение

Этот этап закрывает разрыв между проверкой callback, доверенным OIDC/JWKS и защищённым Windows-хранилищем. Реализованы только детерминированные операции подготовки запроса, проверки синтетического ответа и атомарного сохранения. **Запросов к OpenAI, входа в аккаунт, реальных токенов и вызовов модели в тестах нет.**

## Контракт

1. Вход разрешён только после проверки `state`, точного loopback-адреса и выданного `client_id`. `OAuthCallbackGuard.consume_private` выдаёт код однократно; старый публичный `consume` продолжает отдавать только очищенный отчёт.
2. Формируется фиксированный `POST https://auth.openai.com/api/accounts/oauth/token` с `application/x-www-form-urlencoded`: `grant_type=authorization_code`, выданный `client_id`, `code`, исходный `code_verifier`, **тот же** `redirect_uri` и `resource=https://api.openai.com/v1`. `client_secret` не добавляется.
3. Результат принимает только код HTTP 200, ограниченный JSON без дублированных ключей и нечисловых констант; `access_token`, `refresh_token`, `id_token`, `token_type=Bearer`, `expires_in` и точный список выданных `scope` обязательны для первой сессии.
4. Подпись ID-токена, `iss`, `aud`, `exp`, `iat`, `nonce` и `sub` проверяются **реальным криптографическим верификатором** по доверенному JWKS до сохранения. Повторный вход не может без разрешённой смены профиля заменить `subject`/`client_id`.
5. Запись выполняется в DPAPI-хранилище через атомарный compare-and-swap (`expected_revision`); `chatgpt.tokens.use.direct` оценивается только по выданному сервером `scope`. Отсутствие разрешения не превращается в право на вывод модели.
6. Обновление использует `grant_type=refresh_token`, сохранённый **выданный** `client_id`, актуальный `refresh_token` и `resource`; поле `scope` в запрос обновления не передаётся.
7. Межпроцессная блокировка `.refresh.lock` захватывается **до чтения refresh-токена** и удерживается до атомарной записи его замены. При неясном сетевом исходе или ошибке записи блокировка сохраняется; **повтор запрещён до сверки внешних эффектов**.
8. При обновлении ID-токен, не подтверждённый новым OIDC nonce, не заменяет ранее проверенный ID-токен. Защищённое хранилище сохраняет исходный подтверждённый экземпляр для последующей интерактивной переавторизации.

## Ограничения (не выдавать за завершённое)

- Сетевой клиент, реальный loopback HTTP listener, запуск браузера, выдача согласия, смена учётной записи и интеграция с Codex App Server **отсутствуют**. Транспорт в тестах — внедрённая функция с синтетическим ответом.
- Настройки повторных сетевых попыток выключены: для вращающихся refresh-токенов ошибка может означать неизвестный результат на сервере. Ручное восстановление нельзя сводить к удалению `.refresh.lock` без проверки состояния OAuth-сессии.
- `earliest_refresh_at` пока не сохраняется в схему credential v1; обновление вызывается не раньше заданного окна около `expires_at`. Прежде чем разрешать настоящий refresh, нужен отдельный gate совместимости поля и подтверждение правил времени на реальном token endpoint.
- Любой иной механизм вывода модели, особенно платный API fallback, **не активируется**.
- Внешние тесты и контроль GitHub CI выполняются только на Windows. Проверка исходников в промежуточной изолированной среде не подтверждает свойства Windows DPAPI.

## Критерии приёмки

- Все локальные тесты, включая подлинную RSA-подпись синтетического ID-токена и негативные сценарии, пройдены.
- Проверка на GitHub-hosted **Windows** прошла на exact SHA исходного коммита; повторного CI для документационного чекпойнта не требуется.
- В журнале нет JWT, `code`, `code_verifier`, `refresh_token`, токенов доступа и содержимого ошибок внешнего сервера.
- Проверки BPR40 и три башни не изменялись.
