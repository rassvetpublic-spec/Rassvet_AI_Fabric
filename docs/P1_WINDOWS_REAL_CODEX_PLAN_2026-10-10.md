# P1 — путь к первой реальной задаче разработки в Rassvet AI Fabric

**Дата:** 10 октября 2026 года. **Статус:** план реализации на основе проверенного Windows-host evidence.
**Язык:** русский. **Главная цель:** не расширять диагностику бесконечно, а получить один управляемый исполнитель Codex, способный выполнить безопасную задачу разработки.

## Подтверждённая исходная точка

- На пользовательском Windows-хосте установленный `codex.exe` ответил на JSONL `initialize` и принял `initialized`; изолированный `CODEX_HOME`, только собственный дочерний процесс, штатное завершение. Исходный архив `RAiF-Windows-RESULT-CODEX-20261010_053301_ff4e0f4a.zip`, SHA-256 `37199d03ec356ad3b220d4d27bd198d2e8c72a2820fc059a971556b5853d3d7f`.
- Ответ handshake — **транспортная проверка**, не подписная авторизация, не доказательство доступности модели и не выполнение задачи.
- Ветка `AG_pather` уже содержит проверенный CP48–51: 9 изолированных записей и 9 credential targets, но live OAuth и смена активного аккаунта НЕ проверены; интерфейс кеша квот недоступен. **Не повторять импорт или патч**.
- Исходный код Fabric: SQLite + lease, чекпойнты, read-only MCP, codex-mock, офлайн-контракты OAuth/JWKS/Windows DPAPI; ещё нет полноценного реального `codex-app` worker.

## Критический путь P1 (по порядку)

1. **P1.1 — управляемый транспорт реального App Server.** Собственный модуль Python stdio: фиксированный исполняемый файл Codex с проверкой пути/типа, окружение без ключей, изолированный `CODEX_HOME`, `initialize`/`initialized`, корреляция JSON-RPC, ограничение размера/времени, безопасное завершение дерева собственных процессов Windows. Негативные тесты: сбой/EOF/timeout/неожиданный запрос разрешений; `fail-closed`. Без `turn/start` и без сетевой авторизации.
2. **P1.2 — подтверждённая сессия, без inference.** Запуск `thread/start` в отдельном тестовом workspace с режимом `readOnly`, считывание идентификатора потока и штатное завершение; при ошибке auth/config запись точного обезличенного error code. `model/list` является справочником, но не доказательством доступа. Сначала mock-контракт, затем **один** пользовательский запуск ZIP+PS1.
3. **P1.3 — первый разрешённый turn.** Отдельный пользовательский gate для реальной подписной авторизации и одного ограниченного модельного обращения. Никакого извлечения ответов из HTML ChatGPT Web, никакого `OPENAI_API_KEY`/платного API fallback. Не включать автоматически.
4. **P1.4 — разработчик в безопасном workspace.** Одна тестовая задача `создать файл → запустить тест → показать diff` в отдельном Git worktree/демо-проекте. Запрещена прямая запись в KAT9I_OS, CKS Canon, RULESHUB, ANTIGRAVITYDATA или CONTROL TOWER до разрешения authority gate. Независимая проверка, checkpoint с SHA Git и восстановление без повторного внешнего эффекта.
5. **P1.5 — первая продуктовая приёмка.** Успешная локальная Windows-задача и отчёт с вердиктом модели, diff, результатами тестов, отсутствием секретов и подтверждённым контролем расхода. Только после этого расширять до Antigravity и нескольких исполнителей.

## Параллельный контур Antigravity

`AG_pather` остаётся независимой веткой. CP48–51 закрыт в рамках read-only отчёта. Следующий CP52 — **проект** контролируемого исследования с учётом пользовательского разрешения, без автоматической ротации аккаунтов или обхода квот. Не блокирует P1 Codex.

## Обязательные правила

- **Windows-only:** `pwsh7`, Git, Python 3.13, Windows Job Objects; не вводить Linux/WSL/Docker в продукт и CI.
- **Пакеты:** одна значимая итерация = ZIP и один PS1 в `D:\ЗАГРУЗКИ`, одна команда `pwsh.exe -NoProfile -ExecutionPolicy Bypass -File ...`; результат ZIP прямо в `C:\GIT\Rassvet_AI_Fabric`.
- **Логирование всех этапов:** timestamp, stage, outcome, exception type/code, SHA-256 evidence и следующий cursor; исключить исходные команды процессов, JWT, cookie, credential values, приватные пути/идентификаторы.
- **Экономия GitHub Actions:** при значимом кодовом рубеже не более одного штатного Windows CI; документационные коммиты не инициируют CI. Не создавать фиктивные push, не запускать Linux.
- **Авторитеты:** чтение CONTROL TOWER и рабочего BPR40 перед любыми мутациями, никакого несанкционированного merge/Canon-promotion и публикации в три башни.
- **Донорские проекты:** самостоятельная реализация; не размещать ссылки или названия доноров в README.

## Приёмка ближайшего этапа

`P1.1 PASS` только после offline mock-тестов + настоящего процесса App Server с безопасной очисткой; `P1.2 PASS` только после реального `thread/start` на Windows без `turn/start`. Никаких заявлений `P1.3 PASS` без разрешённого фактического модельного результата.
