# Проверка ID-токенов и проект Windows Token Vault — этап 09.4

**Дата:** 10 октября 2026 года. **Статус:** криптографическая проверка ID-токена реализована офлайн; DPAPI проверяется только на синтетических данных. **Официальный язык:** русский.

## Решение

1. `oauth_readiness.py` отвечает за подготовку PKCE и защиту одноразового callback.
2. `oauth_identity.py` принимает **только** выданный `client_id`, одноразовый `nonce` и доверенный набор JWKS, полученный вызывающим модулем по TLS из OpenID Discovery `https://auth.openai.com/.well-known/openid-configuration`. Источник доверия задаётся **извне**; токен не вправе указать свой JWKS.
3. Проверка JWT выполняется через дополнительный пакет `PyJWT[crypto]`, не через собственную реализацию RSA. Разрешён только `RS256`, ключ выбирается по единственному `kid`; ключи с приватной частью и ключи для шифрования отвергаются. Проверяются подпись, `iss`, `aud`, при необходимости `azp`, `sub`, `iat`, `exp`, `nbf` (если присутствует), исходный `nonce`. Тексты ошибок и публичный отчёт не содержат JWT или subject.
4. Наличие подтверждённой личности — **не** доказательство права пользоваться подпиской. После проверки ID-токена отдельно сверяются выданные token endpoint scopes, включая `chatgpt.tokens.use.direct`; реальная доступная квота подтверждается только поддерживаемым вызовом модели и ответом сервера.
5. `windows_vault.py` подготавливает обезличенный идентификатор записи и системный каталог `%LOCALAPPDATA%/Rassvet_AI_Fabric/oauth_v1`. `WindowsUserDPAPI` обёртывает `CryptProtectData` и `CryptUnprotectData` **текущего пользователя** без `CRYPTPROTECT_LOCAL_MACHINE`. На Windows CI модуль тестируется с вымышленным BLOB. На других ОС включение DPAPI блокируется.

## Требования к следующему этапу хранения

1. Использовать каталог пользовательского профиля Windows, не рабочий Git-каталог. Отдельная запись должна привязываться к подтверждённым `issuer`, `issued_client_id` и `sub`; одинаковый email не означает одинаковый аккаунт. Уровень каталога — текущий пользователь; ACL необходимо установить **и проверить readback**, не полагаясь только на chmod.
2. Прежде чем создавать или читать файл, отвергать символьные ссылки, junction и другие reparse points, в том числе во всех компонентах пути. Для защиты от TOCTOU предпочтительно открывать файл Windows API с безопасным режимом, а не только предварительно проверять путь.
3. Шифровать перед записью через DPAPI текущего пользователя. Сохранять данные атомарно в том же каталоге, исключать резервные незашифрованные копии, не публиковать в Git, журналы и чекпойнты; ограничить размер записи.
4. Все поля одного набора токенов, включая **ротируемый** refresh-токен, заменять вместе; после частичного сбоя блокировать использование и требовать сверки, чтобы не потерять актуальный refresh-токен.
5. Не выполнять автоматическую смену учётной записи ради обхода квоты и никогда не переходить на платный API без отдельного явного разрешения.
6. При выходе из профиля удалять локальные данные; это **не равно** отзыву разрешения в ChatGPT Settings. DPAPI защищает секреты на диске, но не от вредоносного процесса с полномочиями того же пользователя.

## Запуск проверок

Полный пакет проверки криптографии (базовое ядро по-прежнему использует стандартную библиотеку):

`python -m pip install -e ".[security]"`

`python -m unittest discover -s tests -v` (при `PYTHONPATH=src` либо установленном пакете).

На Windows GitHub Actions проверяются Python 3.11 и 3.13, генерация тестовых RSA-ключей и реальная криптография DPAPI с **вымышленными** данными. Отсутствие реальной авторизации не может быть обозначено как PASS подписного inference.
